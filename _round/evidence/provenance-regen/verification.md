## 1. 수리 — 원장을 손으로 나열하지 않고 적용 결과에서 생성

`POLICY_GROUPS` 계열 표를 신설했다. **치환 규칙과 원장 기재문(`what`·`why`)을 한 곳에 묶는다.**

```
POLICY_GROUPS = [ boundary · clarify · account-state · credential ]
applyBodyPolicy(dir) → { groups: {계열: {files,hits}}, residual, … }
buildModifications({pin, npxPin, groups}) → [npx핀, …계열 4개]  ← install() 이 이것을 쓴다
```

`install()` 의 하드코딩 3항목 배열을 `buildModifications(...)` 호출로 교체했다.
이제 **계열을 추가하면 치환·원장·검사가 함께 늘어난다** — 한쪽만 늘어나는 상태가 이번 반증의 원인이었다.
설계 원리는 worker 제안 그대로다: 설치 검증의 예외 개수를 `PENDING_JUDGMENT.length` 로 뽑은 것과 같다.

건수 0 인 계열도 항목을 남긴다 — 「이 판본에는 그 결함이 없었다」도 기록이고,
항목이 사라지면 원장을 읽는 사람이 **「검사하지 않았다」와 구별할 수 없다.**

## 2. ★내 이전 주장 하나를 실측으로 철회한다 (순서 의존)

`skills-install.js` 주석에 「A′ 를 먼저 돌리면 경계 위반이 살아남으므로 B 계열을 먼저 돌려야 한다」고
적어 뒀고, 그 통찰을 master 에게 보고해 **규약으로 승격됐다.** 이번에 계열을 분리하면서
순서를 실제로 재보니 **그 주장은 틀렸다.**

상류 원문(`ffc76fe~1`)에 양쪽 순서로 적용한 결과:

```
B 먼저 → 경계위반 잔존: false
A 먼저 → 경계위반 잔존: false
두 결과 바이트 동일  : true
```

원인: B 계열 패턴은 A 계열이 건드리지 않는 부분에 걸린다 —
`결제 자동화 금지는 generic fallback…` · `승인되면 결제를 실행` · `돌쇠…확인했다`.
A′ 는 `` `clarify`로 ``·`` `clarify` 승인 후 `` 토큰만 바꾸므로 B 패턴의 매칭 조건을 훼손하지 않는다.

**유효한 교훈과 무효한 주장을 갈라 적는다:**
- **유효** — 기전(도구 이름)만 고치면 목표(결제를 완료하라)는 남는다. **패턴이 따로 있어야** 잡힌다.
  B″·B‴ 가 실제로 그렇게 발견됐다. 이 부분은 그대로 유효하다.
- **무효** — 「적용 순서 때문에 위반이 살아남는다」. 측정으로 반박됐다. 주석과 selftest 문구를 정정했다.

B 계열을 앞에 두는 배치는 **유지**했다. 이유는 순서 의존이 아니라, 패턴이 나중에 좁아지면
순서가 실제로 문제될 수 있고 앞에 두는 비용이 0 이기 때문이다 — 근거를 바꿔 적었다.

## 4. selftest 신규 검사 3건 (검사 공백을 닫는다)

| # | 검사 | 무엇을 막는가 |

| 2 | 건수 0 계열도 항목을 남긴다 | 0건 계열이 목록에서 빠져 「미검사」와 구별 불가해지는 것 |
| 3 | **재생성 = 커밋본 정합** | 코드 계열수와 커밋본 항목수가 갈리는 것 — **이번 반증 그 자체** |

검사 3은 계열명까지 대조한다. 다만 두 가지를 정규화한다:
- **휘발성 접미**: 커밋본 2항목에 손으로 붙인 파일·줄 목록(`… (coupang 137·142 …)`)이 있다.
  그 줄번호는 **치환 직후 이미 낡는다**(내용이 바뀌면 줄이 밀린다). 그래서 계열 표의 `what` 은
  변경 내용만 적고, 정량은 files/occurrences 가, 줄 단위 감사는 `install-skills/verification.md`
  §9~§12 표가 진다. 대조 시 이 접미를 벗긴다.
- **백틱**: 커밋본은 백틱 없이, 계열 표는 백틱을 달고 적혀 있다. 마크다운 서식이지 내용이 아니다.
  서식 차이로 검사가 깨지면 검사가 내용을 못 보고 표기를 보게 된다.

⚠따라서 **다음 실제 재설치 때 2항목의 `what` 문구는 바뀐다**(낡은 줄 목록이 빠진다).
계열·건수는 그대로다. 숨기지 않고 여기 적는다.

★검사 3은 작성 직후 **실제로 걸렸다** — `account-state` 와 `credential` 이 커밋본과 달랐고,
원인이 위 두 정규화 대상(줄 목록 접미·백틱)이었다. 검사가 만들어지자마자 갈림을 잡아낸 것이다.

## 6. 재지 못한 것 (고지)

1. **상류 tarball 에서의 전 구간 실제 설치는 하지 않았다.** `install()` 은 네트워크로 tarball 을
   받아야 하고, 티켓은 로컬 커밋까지로 범위를 정했다. 그래서 원장 생성 로직을 **순수 함수
   (`buildModifications`)로 분리**해 단위 검사하고, 계열 건수는 상류 원문 트리에 실제 적용해
   측정했다. `pinNpxVersion` 의 177/479 만 재현하지 못했다(§3).
2. **첫 멱등 측정은 무효였다.** 앞선 시도가 해시 단계에서 죽으면서 트리를 이미 치환해 버려
   1회차 건수가 0 으로 나왔다. 그대로 「멱등 통과」로 읽으면 **공허한 통과**였다 —
   기준본을 새로 뽑아 1회차 6/5/7/10 을 확인한 뒤에야 유효한 측정이 됐다. 그 사실을 남긴다.
