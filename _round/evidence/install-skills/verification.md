### 4-3. 종료 코드 — 가설이 틀렸음을 실측으로 확인

스킬 확인을 마지막으로 옮기면 스크립트 종료 코드가 그것에 물려
`setup.ps1:87`(`if ($LASTEXITCODE -ne 0) { throw "설치 실패" }`)이 설치를 실패로 뒤집을 것이라고
**추정했으나, 측정 결과 그렇지 않았다.**

```
tail(if 블록으로 끝남, node exit 1)         -> exit 0
tail(네이티브 명령이 문자 그대로 마지막)     -> exit 0
대조군: 명시적 `exit 3`                      -> exit 3   ← 비0 감지 가능함을 확인
대조군: `throw "boom"`                       -> exit 1
install.sh 꼴(스킬 확인 실패)                -> exit 0
install.sh 꼴(스킬 확인 성공)                -> exit 0
```

대조군이 비0을 정확히 잡아냈으므로 위 0 들은 계측 실패가 아니다.
→ **살아 있는 버그는 없었다.** `install.ps1` 의 `exit 0` 은 버그 수정이 아니라,
이 블록이 파일 맨 끝이라 향후 편집 한 번으로 성질이 조용히 바뀌는 것을 막는 **회귀 고정**이다.
코드 주석과 selftest 주석 모두 이 사실대로 고쳐 적었다(처음 쓴 주석은 틀린 근거를 담고 있었다).

## 8. E1 게이트 최초 제출 실패 기록 (은닉하지 않는다)

최초 제출은 **exit 5** 로 거부됐다. 오류 원문:

```
evidence-artifact required(5): 신선도 실패(mtime<created_at-fallback):
_round/evidence/install-skills/verification.md — 태스크 시작 전 파일은 증거 아님
(기계 검사 3종 — 실존·비어있지않음·신선도 mtime≥앵커)
```

**게이트가 정상 동작한 것이다 — 결함이 아니다.** 다만 원인은 구조적이다.

`javis_task.py` 는 100행의 무조건 `import fcntl`(POSIX 전용) 때문에 이 작업 **전 구간에서
Windows 에서 실행 자체가 불가능**했다. 따라서 착수 시점에 태스크를 만들 수 없었고,
작업이 끝난 뒤 master 가 크로스플랫폼 shim 으로 고친 다음에야 태스크를 만들 수 있었다.
그 결과 **태스크 `created_at`(17:09:31) 이 증거 파일 mtime(16:45:52) 보다 뒤**가 되어
신선도 검사가 정당하게 거부했다.

즉 이것은 「도구가 죽어 있던 기간에 수행된 작업」이 사후 등록될 때 **필연적으로** 발생한다.
해소 경로는 셋뿐이고, 고른 것은 ①이다.

1. **다시 재서 진짜로 새 산출물을 만든다** ← 채택(§7). 검사가 요구하는 것이 실제로 충족된다.
2. `--skip-reason` 으로 통과시킨다 → master 가 기각했다. 우회를 제도화하기 때문이다.
3. `touch` 로 mtime 만 올린다 → **하지 않았다.** 검사를 속이는 것이고,
   「조항은 있고 기전은 없는 상태」를 우리가 직접 만드는 셈이다.

  실제 결제·예약은 사용자가 공식 표면에서 직접 마친다 (jini 경계 — 상류 원문이 예외를 두어
  결제 완료를 지시했으나 우리 정책으로 대체했다)」

  삼았으나 우리 정책으로 대체했다)」

### 9-3. ★B″ 는 아무도 지목하지 않은 것이다 (범위 확대의 산출물)

독립검증이 지적한 B′ 는 `## Notes` 절 2곳이었다. 범위를 출고 페이로드 전체로 넓히자
**`## Done when` 절에 결제 완료를 성공 조건으로 못박은 문장이 4곳** 더 나왔다.

**A′ 만 고치면 부족하다**는 것이 핵심이다 — 도구 이름을 실재 기전으로 바꿔도
「결제를 완료해야 끝」이라는 **목표**가 남으면 모델은 여전히 결제로 향한다.
기전을 고치고 목표를 두면 오히려 문장이 그럴듯해져 위험이 가려진다.
그래서 치환 순서를 **B 계열 → A′** 로 강제했고 selftest 가 그 순서를 고정한다.

### 9-4. 손대지 않고 판단 요청한 것

### 10-3. 판단 대기 예외 1건 — 패턴을 지워 0 을 만들지 않았다

`iros-registry-automation/instruction.md:219` 「테스트용 1건을 장바구니에 담는다」는 **고치지 않았다.**
이 스킬은 장바구니 담기가 **선언된 기능 자체**다(등기부등본을 담아 두고 사용자가 직접 결제·열람).
coupang 은 이름이 `-search` 라 장바구니를 빼도 목적이 손상되지 않지만 이쪽은 다르다 —
**master 의 coupang 근거가 그대로 옮겨가지 않는다.**

스캐너 패턴을 지워 잔존 0 을 만드는 방법은 쓰지 않았다. 그건 검사를 속이는 것이고 오늘 우리가 금지한

**잔존 0 과 예외 1 은 다른 말이다.** selftest 가 예외 수·사유 유무·위치 형식을 고정한다.

### 10-4. 미처리 별건 — 자격증명 계열 10곳 (판단 요청 · 손대지 않았다)

전수 재스캔 중 **또 하나의 부재 도구 지시 계열**이 나왔다. `request_vault_credential` ·
